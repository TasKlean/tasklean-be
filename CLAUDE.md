# CLAUDE.md

For deep context — domain model, entity relationships, database schema, API catalog, security architecture, coding patterns, and gotchas — see [PROJECT_BIBLE.md](PROJECT_BIBLE.md).

## Quick reference

```bash
# === Everyday ===
./mvnw spring-boot:run              # Start API on :8080 (dev profile, with seed data)
./mvnw clean compile                # Compile (catches errors fast)
./mvnw test                         # Run all tests

# === Database ===
docker-compose up -d                   # Start local Postgres (5432) + Mailpit (SMTP 1025, UI 8025)
docker-compose stop                    # Stop both (keeps data)
docker-compose down -v                 # Wipe database completely (fresh start)
# Sent mail: http://localhost:8025 - no account, no quota. Mailpit holds the last 500 in memory.

# === Testing ===
./mvnw test                              # Run all tests
./mvnw test -Dtest=JwtServiceTest        # Run single test class
./mvnw test -Dtest="AuthServiceTest#login_validCredentials_returnsToken"  # Single method
./mvnw test -Dtest="com.tasklean.api.auth.**"  # Run all tests in a package

# === Build & package ===
./mvnw clean package                 # Build JAR

# === API contract (dev profile) ===
# Live spec:   http://localhost:8080/v3/api-docs      (always reflects the running code)
# Swagger UI:  http://localhost:8080/swagger-ui.html  (paste a token once, then click through requests)
# docs/openapi.json is rewritten by OpenApiSpecExporter on every dev startup when the spec changed
# — no command to run. Commit it when it changes; never hand-edit it.

# === Database inspection ===
docker exec -it tasklean-db psql -U dev -d tasklean_dev    # Open psql shell
docker exec tasklean-db psql -U dev -d tasklean_dev -c "\dt"  # List tables
```

Java 21, Spring Boot 4.1.0, Maven 3.9.16.

### Seed data

Dev profile auto-loads seed data via Flyway repeatable migration (`src/main/resources/db/seed/R__seed_data.sql`). Runs on every startup if checksum changed. To reset to clean seeded state: `docker-compose down -v` then restart.

## Architecture

Package root: `com.tasklean.api`

- **`domain/<entity>`** — one package per aggregate. Each has: `Entity.java`, `Controller.java`, `Service.java`, `Repository.java`, plus `dto/EntityRequest.java` and `dto/EntityResponse.java`. Entities with uid (`user`, `group`, `task`) use uid as the external identifier in REST paths. Other entities (`category`, `tag`, `groupmember`, `device`, `taskcompletion`) use Long id. `usersettings` and `notificationsettings` are self-scoped with no user identifier in the path (created lazily on first write — one row per user, and one row per user per notification type; their write paths use a `TransactionTemplate` rather than `@Transactional` so a lost insert race can retry in a fresh transaction). Read-only entities (`notification`, `auditlog`) have no request DTO.
- **`auth`** — `AuthController` (register/login/verify/resend/forgot-password/reset-password/refresh/logout/logout-all/google/2fa-verify endpoints), `AuthService` (credential validation, user creation), `GoogleOAuthService` (verifies a Google ID token via `GoogleIdTokenVerifier`, then finds/links/provisions the user — see `config/GoogleOAuthConfig`). `SessionRotator` (revoke every session, then reissue the caller's current device — shared by account-security and two-factor changes). DTOs: `LoginRequest`, `RegisterRequest`, `GoogleAuthRequest`, `AuthResponse` (includes `refreshToken` field).
  - **`auth/jwt`** — `JwtService` (token generation/validation, claims incl. platform `role`), `JwtAuthenticationFilter` (extracts Bearer token, builds an `AuthPrincipal` from claims — **stateless, no DB load** — and sets SecurityContext with a `ROLE_<role>` authority), `AuthPrincipal` (claims-derived principal record), `JwtAuthenticationEntryPoint` (401 JSON response). Deactivation/role changes take effect at token refresh, not per-request (bounded staleness = access-token TTL).
  - **`auth/verification`** — `VerificationService` (email verification code generation, validation, resend), `EmailVerification` (entity), `EmailVerificationRepository`. DTOs in `verification/dto`: `VerifyEmailRequest`, `ResendVerificationRequest`.
  - **`auth/refresh`** — `RefreshTokenService` (create bound to the caller's device + new-sign-in email, rotate on refresh keeping the same device, per-device logout + logout-all, scheduled cleanup), `RefreshToken` (entity, nullable `device_id` FK), `RefreshTokenRepository`. DTOs in `refresh/dto`: `RefreshRequest`. Sign-in sessions = a `device` row + its live refresh token (see the `device` domain package and `common/web/RequestContext`, which reads the `X-Device-Id`/UA/IP off the request).
  - **`auth/passwordreset`** — `PasswordResetService` (single-use, SHA-256-hashed, 15-min reset tokens; revokes all sessions on reset; enumeration-safe), `PasswordResetToken` (entity), `PasswordResetTokenRepository`. DTOs in `passwordreset/dto`: `ForgotPasswordRequest`, `ResetPasswordRequest`. Token generation/hashing is shared via `common/SecureTokens` (also used by refresh tokens).
  - **`auth/twofactor`** — two-factor authentication. Provider seam: `provider/TwoFactorProvider` (port: `enroll`/`verify`, returning the matched TOTP time step so callers can reject a replay) and `provider/LocalTotpProvider` (RFC 6238 via `com.atlassian:onetime`, SHA-1/6-digit/30s for authenticator-app compatibility, ±1 step skew) — same port-and-adapter shape as `BucketRegistry`, so a hosted factor service can replace the local one. Persistence: `UserTwoFactor` (one per user, `provider`/`factor_ref`/`secret_encrypted`/`digest`/`is_enabled`/`last_used_step`), `TwoFactorRecoveryCode` (hashed, single-use), `TwoFactorChallenge` (a pending sign-in: hashed opaque token, expiry, attempt counter) + their repositories. `TwoFactorService` + `TwoFactorController` at `/api/account/2fa` cover enrollment (status, setup, enable, disable, regenerate recovery codes): the secret is stored unconfirmed until a code proves it, enable/disable rotate sessions, and `consumeCode` is the shared entry point that spends a code (authenticator step replay guard via `last_used_step`, or a single-use recovery code) — it writes without opening a transaction, so callers supply one. `TwoFactorChallengeService` gates sign-in: `challengeIfEnabled` (called from `AuthService.login` and `GoogleOAuthService`) withholds the tokens and returns `AuthResponse.twoFactorRequired(challengeToken)`, and `verify` (public `POST /api/auth/2fa/verify`) spends the code and issues them. The challenge is an opaque SHA-256-hashed token, **never a JWT** — `JwtAuthenticationFilter` would accept a purpose-scoped token as a full session (`extractRole` defaults to `USER`). 5-minute TTL, 5 attempts, a new challenge drops the previous one, and an hourly `@Scheduled` purge clears finished rows. `verify` is deliberately **not** `@Transactional`, like `AuthService.login`, so the attempt counter and `LOGIN_FAILED` entry survive the thrown exception.
  - **`auth/account`** — authenticated self-service account security at `/api/account` (not public, unlike `AuthController`): `AccountController` + `AccountService` (change/set password, connected accounts = Google link/unlink, deactivate). Change/set-password revoke all sessions then reissue the current device (return new tokens); Google link requires the Google email match the account email and reuses `GoogleOAuthService.verifyLinkToken`; unlink is blocked without a password (lockout guard); deactivate soft-deletes + revokes all sessions. DTOs in `account/dto`: `ChangePasswordRequest`, `SetPasswordRequest`, `DeactivateAccountRequest`, `ConnectedAccountsResponse`.
- **`common`** — `BaseEntity` (mapped superclass with `dateCreated`/`dateUpdated`), `ApiResponse<T>` (response envelope with `success`/`error` factory methods), `ErrorMessages` (centralized user-facing message constants: "not found" strings, the generic platform messages, and the auth-failure messages thrown by more than one service), `exception/` (`ResourceNotFoundException`, `DuplicateResourceException`, `BusinessRuleException`, `GlobalExceptionHandler` handling 400/401/403/404/405/409/503 plus a catch-all 500, and `ApiErrorController` — a custom `ErrorController` that renders every `/error` dispatch as the JSON `ApiResponse` envelope instead of the Whitelabel HTML page), `SecretCipher` (AES-256-GCM for secrets that must be recoverable rather than merely comparable — the TOTP secret; key from `TWO_FACTOR_ENC_KEY`, validated at startup), `email/` (`EmailTemplates` — every email declared as a list of `EmailBlock`s from `email/html/`, each template owning its copy, its structure *and* its `Delivery`; `EmailLayout` renders that one declaration **twice**, as the HTML document and as the plain-text part, so the two can never drift; `EmailService.send(to, content)` — the one transport out to Spring Mail, sending multipart with the logo attached inline, Mailpit from docker-compose in dev and a hosted sandbox outside it, with the provider as env config only so swapping it touches no code. A caller picks a template, never a subject, a body or a failure policy — add an email by adding a template, not a send method; add a kind of content by adding a block, and let the block escape what it interpolates). **Every template carries a `Delivery`** - `ADVISORY` is caught and logged so a provider outage cannot undo an operation that already happened, `ESSENTIAL` rethrows as `EmailDeliveryException` (503, `EMAIL_DELIVERY_FAILED`). Pick it by asking whether the endpoint has a branch that sends *nothing*: if it does, the email must be advisory however important it is, or the error reveals which branch ran - see PROJECT_BIBLE **Email delivery policy**), `logging/` (`RequestLoggingFilter` — per-request MDC + one summary line; `LogFields` — MDC key constants), `web/` (`RequestContext` — device id / user-agent / client IP off the current request; `ClientIpResolver` — the single place the end user's IP is resolved, and whether it came from a trusted hop). **Reading the client IP: `clientIp()` to record a value, `trustedClientIp()` to *overwrite* one** — an untrusted request resolves to the BFF's own egress address, so overwriting a stored user address with it would put infrastructure's location on the devices screen. Device activity (`last_used` + `ip_address`) has exactly one writer, `DeviceService.recordActivity`; keep it that way, since the two drifting apart was the bug.
- **`config`** — `SecurityConfig` (stateless JWT filter chain + rate-limit filter, BCrypt encoder), `JwtConfig` (`@ConfigurationProperties` for `jwt.secret`/`jwt.expiration`/`jwt.refresh-expiration`), `CorsConfig` (configurable origins, credentials enabled), `ClockConfig` (UTC `Clock` bean for consistent timestamps). `@EnableScheduling` on `TaskleanApiApplication` for refresh token cleanup job. Spring Boot Actuator exposes a public `/actuator/health` endpoint (health only, no details) whitelisted in `SecurityConfig`.

## Conventions

- **Primary keys**: `id_<entity>` column, `BIGSERIAL` in SQL, `Long` with `@GeneratedValue(IDENTITY)` in Java.
- **Soft deletes**: all entities use `is_active` boolean, never hard-delete rows.
- **UIDs**: user-facing identifier (`uid` column) separate from internal PK. Present on `user`, `group`, `task`.
- **Timestamps**: `BaseEntity` provides `date_created`/`date_updated` via Hibernate `@CreationTimestamp`/`@UpdateTimestamp`. Entities not extending `BaseEntity` (`GroupMember`, `Notification`, `AuditLog`, `TaskCompletion`, `TaskTag`, `TwoFactorRecoveryCode`, `TwoFactorChallenge`) manage their own `date_created`.
- **Flyway migrations**: `src/main/resources/db/migration/V<N>__description.sql`. Next available version is V23.
- **Row Level Security**: every table has RLS enabled (V14) to close Supabase's PostgREST/anon-key access path; the backend connects as the table owner and bypasses it. **Any migration that creates a new table must end with `ALTER TABLE <name> ENABLE ROW LEVEL SECURITY;`** — no policies (deny-all through the API is the goal), and never `FORCE ROW LEVEL SECURITY` (it would make the owner obey policies too).
- **Profiles**: `application.properties` (base — shared config including database, JWT, mail via env vars), `application-dev.properties` (verbose logging, seed data, Flyway clean enabled, 1-year JWT), `application-prod.properties` (minimal logging, ECS JSON structured logging, Flyway clean disabled). Active profile set via `SPRING_PROFILES_ACTIVE` env var (defaults to `dev`).
- **Lombok**: `@Getter @Setter @NoArgsConstructor @AllArgsConstructor @Builder` on entities. Use `@Builder.Default` on fields with initializers. Use `@RequiredArgsConstructor` for constructor injection in services/controllers.
- **Reserved words**: `user` and `group` table names are quoted (`"user"`, `"group"`) in both `@Table` annotations and migrations.
- **API response**: all endpoints return `ApiResponse<T>` envelope. Use `ApiResponse.success(data)` or `ApiResponse.error(message)`. An optional machine-readable `code` (via `error(message, code)`) is serialized only when set, so clients can branch on it instead of the message — which also keeps the FE free to localize its own copy. Codes are constants in `common/ErrorCodes.java` — never inline strings. A 401 carries one by throwing `AuthFailureException(message, code)` (a `BadCredentialsException` subclass the handler reads the code off; `EmailNotVerifiedException` extends it). Keep a code as coarse as the behaviour it drives, and **never add one that narrows a deliberately vague message**: every unusable two-factor challenge shares `TWO_FACTOR_CHALLENGE_INVALID`, and the generic login failure stays uncoded because a code would reveal which of email/password was wrong (`AuthServiceTest` guards this).
- **Timestamps are UTC**: two mechanisms, both pinned to UTC. (1) Service-set times use an injected `Clock` bean (`ClockConfig`) — never call `LocalDateTime.now()` without it, use `LocalDateTime.now(clock)`. (2) Hibernate-managed times (`@CreationTimestamp`/`@UpdateTimestamp` on `BaseEntity` and the entities that declare their own) read the **JVM default zone**, not the `Clock` bean, so `TaskleanApiApplication.main` pins the JVM default to UTC before startup. Don't remove that call — without it a non-UTC host writes those columns in local time while service-set columns stay UTC, putting two time regimes in one table. Tests use `@Spy Clock clock = Clock.systemUTC()` and `LocalDateTime.now(ZoneOffset.UTC)` for fixture data.
- **Error messages**: user-facing strings are centralized in `common/ErrorMessages.java` - "not found" messages, the generic platform ones (access denied, rate limited, internal error), and every auth-failure message thrown from **more than one service**. Use constants from there instead of inline strings; a message thrown from exactly one place may stay inline. Centralizing the shared auth ones is deliberate, not tidiness: each is the human half of an `ErrorCodes` value, so the copies must stay identical - a service that reworded its own copy would hand the FE one code with two messages, and on the login path a more specific variant would leak account state. The password-policy messages are the one exception (see below).
- **Password policy**: registration passwords go through `@ValidPassword` (`common/validation/PasswordPolicyValidator`) — a 1:1 mirror of the frontend's `tasklean-fe/src/lib/validation/password/policy.ts` + `rules.ts` (only the first failing rule is reported; messages are intentionally inline, not `ErrorMessages`, to match the FE verbatim). Reuse `@ValidPassword` for any future password field (e.g. change-password); never re-implement the rules. Change the policy → update both implementations **and** the shared vectors (`src/test/resources/password-policy-vectors.json`, run by `PasswordPolicyContractTest`), which fail if the two drift.
- **Logging**: SLF4J via Lombok `@Slf4j` (never `System.out`). Levels: **ERROR** (unexpected failures / 500s — only the catch-all in `GlobalExceptionHandler` logs a stack trace), **WARN** (handled-but-abnormal, security events like failed auth), **INFO** (significant business events, e.g. entity created/deleted — log the `uid`, not full entities), **DEBUG** (dev-only flow detail). **Never log** secrets, password hashes, JWTs/refresh tokens, verification codes, or full request/response bodies (PII). Correlation fields (`requestId`, `userId`) are auto-injected into MDC by `RequestLoggingFilter` + `JwtAuthenticationFilter`, so every line within a request already carries them — don't pass them manually. **Baseline is automatic**: every endpoint gets a request-summary line and centralized exception logging for free; a new feature only adds an explicit `INFO` for a genuine business event. Prod emits ECS JSON to stdout (`logging.structured.format.console=ecs`) for log-drain ingestion (Kibana/Grafana/Loki); dev stays human-readable. Logs are ops telemetry — distinct from the DB-persisted audit trail; don't duplicate it.
- **Audit trail**: any mutating service method on an audited aggregate must write an audit entry via `AuditLogService.recordEvent(entityType, entityId, action, message, group)` — audited aggregates are `Task`, `Group`, `GroupMember`, `Category`, `Tag`, `TaskCompletion`, plus auth/account events on `User` (register, login, logout, account deleted/deactivated, profile update, email verified, password reset/changed/set, Google linked/unlinked, two-factor enabled/disabled, recovery code used/regenerated, and `LOGIN_FAILED` on every login rejection where the user is known). Call `recordEvent` *after* the save, inside the same `@Transactional` method so the entry commits atomically with the change (the exception is `login()`, deliberately non-transactional so failed-login entries survive the thrown `BadCredentialsException`). Use `AuditEntityType` / `AuditAction` constants — never inline strings. Pass the owning `Group` so the acting member is attributed; pass `null` only for group-less events. `recordEvent` resolves actor and IP itself from `AuditContext` — don't pass them. **Self-service account events run on anonymous endpoints (no caller in the security context), so use `recordAccountEvent(userId, action, message)` instead — it sets the actor to the subject so `actor_user_id` is populated.** Entries are never updated or deleted (append-only).
- **Authorization (RBAC)**: enforced declaratively with Spring method security (`@EnableMethodSecurity`), not with checks scattered in services. Two role systems: **platform role** (`User.role`, in the JWT) via `@PreAuthorize("hasRole('ADMIN')")` — a `RoleHierarchy` bean makes `SUPER_ADMIN → ADMIN → USER`, so check the *lowest* role that should pass; and **group role** (`GroupMember.role`, relationship-based) via the `@groupSecurity` bean referenced in the expression (e.g. `@groupSecurity.isAdmin(#uid)`, `isMemberOfGroup(#groupId)`, `canManageMember(#id)`), which resolves the caller's active membership of the target group. Self-access uses `@accountSecurity.isSelf(#uid)`. **Every new endpoint that isn't public must carry a `@PreAuthorize`** stating who may call it (a missing one is an access-control hole — the default is only `authenticated()`). Return the *lowest* privilege that works; ADMIN is read-only across the platform, only SUPER_ADMIN does destructive/role-granting actions. Denials surface as 403 via `GlobalExceptionHandler`.
- **Rate limiting**: token-bucket (Bucket4j) in `RateLimitFilter`, in the security chain after `JwtAuthenticationFilter`. Tiers live in `RateLimitProperties` (`ratelimit.*`, overridable per env). An **authenticated** request must pass **both** a per-user and a per-IP bucket; **unauthenticated** requests are limited per IP by the endpoint tier (auth/register/refresh/two-factor-verify, else the api-per-IP backstop). **Per-IP keys come from `ClientIpResolver`, never `getRemoteAddr()`** — behind Cloudflare the socket address is an edge node shared by unrelated users, so keying on it let one abuser exhaust a tier for everybody; the resolver also narrows IPv6 to its /64 so a user cannot rotate inside their own prefix. Over-limit → **429** with `Retry-After`, written as raw JSON in the filter (filters run before MVC, so `GlobalExceptionHandler` doesn't see them). In-memory via `CaffeineBucketRegistry`; the `BucketRegistry` interface is the Redis seam for when the app runs >1 instance. When adding an endpoint that needs a non-default limit, add a tier to `RateLimitProperties` and branch on it in `RateLimitFilter` — don't scatter limiting logic elsewhere. Tiers come in two shapes: **alternative** (the unauthenticated auth/register/refresh tiers *replace* the default for that path) and **additive** (the `join` tier for `POST /api/groups/join` stacks *on top of* the per-user and per-IP api buckets). An authenticated endpoint that needs a tighter limit must be additive — it lives inside the `userId != null` branch, which returns before the path checks below it, so a tier placed with those would be dead code.
- **Comments**: three kinds, each with a specific job. Keep them current — a stale comment is worse than none, so update or delete a comment whenever you change the code beneath it.
  - **File header** — every `.java` file opens with a Javadoc block (`/** ... */`) giving a one-to-three-line overview of the file's *responsibility* (what the class is for, not how it works). Trivial DTOs and entities where the name says everything may use a single line or omit it.
  - **Method-level** — public and protected methods get a Javadoc comment (`/** ... */`): a sentence describing what the method does, followed by `@param` for **every** parameter, `@return` for **any** non-`void` return, and `@throws` for each exception a caller should anticipate (e.g. `ResourceNotFoundException`). A no-argument `void` method needs only the description. Private helpers don't need Javadoc; comment them inline only when non-obvious.
  - **Applies to all logic-bearing classes** — services, controllers, filters, config, and other components. Trivial data carriers (entities, request/response DTOs) are exempt from the file header and method Javadoc.
  - **Inline** — use `//` on its own line *above* the code (not trailing) to explain the *why* behind complex, non-obvious, or unconventional logic. Explain intent and decisions; never restate what the code plainly does (`// increment i` is noise).
- **API contract**: `docs/openapi.json` is the generated contract the frontend generates its types from. It is produced by springdoc from the controllers, DTOs and Bean Validation annotations — **never hand-edited**. `OpenApiSpecExporter` (dev profile only) rewrites it on startup when it differs, so changing an endpoint and restarting is all that's needed; commit the result alongside the code change so the diff shows what the API did. Operation and schema descriptions come from **existing Javadoc** via therapi, so there are no `@Operation` annotations to keep in sync — improving a method's Javadoc improves the spec. **Every new controller must carry a `@Tag`** (name + one-line description) — without it springdoc derives an ugly `foo-controller` tag and Swagger UI ends up half hand-named, half machine-named. Nothing fails, which is exactly why it has to be a rule. A new **public** endpoint additionally needs an empty `@SecurityRequirements` to opt out of the global bearer requirement, alongside its `SecurityConfig` whitelist entry. Two things the spec deliberately does not express: role requirements (springdoc does not read `@PreAuthorize`, so it states only that a token is needed) and per-operation `404`/`409` (too operation-specific to attach by rule — see `OpenApiConfig`). Behavioural rules live in [PROJECT_BIBLE.md](PROJECT_BIBLE.md); the spec is authoritative on shapes only.
- **Commit message prefixes**: used for auto-versioning on production releases. `fix:` → patch bump, `feat:` → minor bump, `BREAKING CHANGE:` → major bump. No prefix defaults to patch.

## Testing

```bash
mvnw.cmd test                                    # Run all tests
mvnw.cmd test -Dtest=JwtServiceTest              # Run single test class
mvnw.cmd test -Dtest="JwtServiceTest#testName"   # Run single test method
```

### Test structure

Tests mirror `src/main/java` under `src/test/java`. Test class naming:
- `<Class>Test.java` — unit tests (no Spring context, mocked dependencies)
- `<Controller>SecurityTest.java` — `@WebMvcTest` slices asserting endpoint `@PreAuthorize` (no DB; caller injected per-request, method security via `MethodSecuritySliceConfig`, service layer `@MockitoBean`)
- `<Class>IntegrationTest.java` — integration tests with `@SpringBootTest` (future, needs Testcontainers)

### Conventions

- **Unit tests only mock direct dependencies** — use `@ExtendWith(MockitoExtension.class)` + `@Mock` + `@InjectMocks`
- **Test method naming**: `methodName_scenario_expectedResult` (e.g., `login_wrongPassword_throwsBadCredentials`)
- **One assertion per concept** — a test can have multiple asserts if they verify one logical outcome
- **Test what matters**: business rules, edge cases, security boundaries. Don't test getters/setters or framework wiring.
- **No test for the sake of coverage** — every test should prove a behaviour or guard a bug
- **Coverage**: JaCoCo generates `target/site/jacoco/jacoco.xml` during `mvn verify`, consumed by SonarCloud. DTOs/config/main class are excluded (`sonar.coverage.exclusions` in `pom.xml`); Lombok-generated getters/setters/builders are excluded via `lombok.config` (`addLombokGeneratedAnnotation`). The gate measures coverage on **new code**.

## Environment

`.env` holds `DATABASE_URL`, `DB_USERNAME`, `DB_PASSWORD`, `JWT_SECRET`, `CORS_ALLOWED_ORIGINS` (comma-separated browser origins; the localhost default lives in the dev profile only — a non-dev profile with it unset fails startup), `APP_BASE_URL` (frontend origin for email links; same dev-only default + fail-fast), `GOOGLE_CLIENT_ID`, `TWO_FACTOR_ENC_KEY` (Base64 of 32 random bytes — AES-256 key for the stored TOTP secret; dev-only default in the dev profile, non-dev fails startup without it), `BFF_HOP_SECRETS` (comma-separated; possession proves a request came from our own frontend, so the `X-Device-Ip` it forwards can be trusted — see PROJECT_BIBLE's **Client IP resolution**. Dev defaults to empty, which trusts nobody; non-dev fails startup without the property. Deliberately no dev *value*: a known trust secret would be accepted if a profile were ever misread), `MAIL_HOST`, `MAIL_PORT`, `MAIL_USERNAME`, `MAIL_PASSWORD` (all four default in dev to the Mailpit container from `docker-compose` — localhost:1025, no credentials — so a fresh clone sends mail with no config; required outside dev), optionally `MAIL_FROM` (sender, defaults to `noreply@tasklean.app`; a real-delivery provider needs a verified address) and `MAIL_SMTP_AUTH`/`MAIL_SMTP_STARTTLS` (both default true, and the dev profile turns them off for Mailpit's plain SMTP), `SPRING_PROFILES_ACTIVE`. **An empty value is not an unset one** — `MAIL_HOST=` in `.env` overrides the dev default with a blank string rather than falling back, which is why `.env.example` keeps these commented out. Loaded natively via `spring.config.import=optional:file:.env[.properties]` in `application.properties`. The `.env` file is gitignored — create it locally from `.env.example`. Never commit real secrets.
